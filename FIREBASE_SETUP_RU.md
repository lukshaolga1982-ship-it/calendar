# Firebase для Teacher Calendar — пошаговая инструкция

Эта инструкция относится к уже созданному проекту Firebase:

- Project ID: `calendar-65f48`
- Auth domain: `calendar-65f48.firebaseapp.com`
- Storage bucket: `calendar-65f48.firebasestorage.app`

Конфигурация уже добавлена в `lib/firebase.ts`, а пакет `firebase` уже включён в `package.json`. Повторно вставлять конфигурацию в код не нужно.

Официальные материалы: [добавление Firebase в web-проект](https://firebase.google.com/docs/web/setup), [вход через Google](https://firebase.google.com/docs/auth/web/google-signin), [создание Firestore](https://firebase.google.com/docs/firestore/quickstart), [Cloud Storage](https://firebase.google.com/docs/storage/web/start).

## 1. Откройте проект

1. Перейдите на [Firebase Console](https://console.firebase.google.com/).
2. Войдите в тот Google-аккаунт, в котором создавали проект.
3. Нажмите проект `calendar-65f48`.
4. Если проекта нет в списке, проверьте, в правильный ли Google-аккаунт вы вошли.

## 2. Включите вход через Google

Без этого кнопка `Войти` на сайте не сможет авторизовать пользователя.

1. В левом меню откройте **Build → Authentication**. В новом интерфейсе раздел может называться **Security → Authentication**.
2. Нажмите **Get started / Начать**, если Authentication ещё не включён.
3. Откройте вкладку **Sign-in method / Способ входа**.
4. В списке провайдеров выберите **Google**.
5. Включите переключатель **Enable / Включить**.
6. В поле **Project support email** выберите свой адрес Google.
7. Нажмите **Save / Сохранить**.

Теперь Firebase разрешает вход через Google. Пользователи не создаются заранее: первая запись появится в **Authentication → Users** после первого успешного входа на сайте.

## 3. Добавьте разрешённые домены

Google-вход работает только на разрешённых доменах.

1. В Firebase откройте **Authentication → Settings / Настройки**.
2. Найдите блок **Authorized domains / Разрешённые домены**.
3. Для локальной проверки убедитесь, что присутствует `localhost`.
4. После публикации сайта нажмите **Add domain / Добавить домен**.
5. Вставьте только домен без `https://` и без пути. Примеры:
   - GitHub Pages: `lukshaolga1982-ship-it.github.io`
   - другой хостинг: `teacher-calendar.example.com`
6. Сохраните изменения.

Если появляется ошибка `auth/unauthorized-domain`, значит домен сайта не добавлен сюда или введён с ошибкой.

## 4. Создайте Cloud Firestore

Firestore хранит облачные уроки и домашние задания.

1. В левом меню откройте **Build → Firestore Database** или **Databases & Storage → Firestore**.
2. Нажмите **Create database / Создать базу данных**.
3. Выберите **Standard edition** и базу `(default)`, если Firebase предлагает выбор.
4. Выберите **Production mode / Рабочий режим**. Сайт начнёт записывать данные после установки правил из следующего раздела.
5. Выберите регион базы.
6. Для пользователя из Европы разумно выбрать ближайший доступный европейский регион. Регион потом обычно нельзя просто поменять, поэтому выбирайте внимательно.
7. Нажмите **Create / Создать** и дождитесь окончания.

Не используйте открытую базу с правилами `allow read, write: if true`. Она позволит посторонним читать и менять данные.

## 5. Установите правила Firestore

В архиве есть готовый файл `firestore.rules`.

1. Откройте **Firestore Database → Rules / Правила**.
2. Удалите текст правил, который сейчас находится в редакторе.
3. Откройте локальный файл `firestore.rules` в Visual Studio Code.
4. Скопируйте его содержимое целиком.
5. Вставьте в редактор правил Firebase.
6. Нажмите **Publish / Опубликовать**.

Правила разрешают доступ только тогда, когда пользователь вошёл и UID в пути совпадает с UID аккаунта:

```text
users/{userId}/...
```

Это значит, что один вошедший пользователь не может открыть данные другого пользователя.

## 6. Как данные появляются в Firestore

Ничего создавать вручную не требуется.

1. Запустите сайт.
2. Нажмите `Войти`.
3. Выберите Google-аккаунт.
4. Создайте или измените урок.
5. Вернитесь в Firebase Console.
6. Откройте **Firestore Database → Data / Данные**.

Должен появиться путь:

```text
users
  └── UID_пользователя
      └── calendar
          └── main
```

В документе `main` находятся массивы `lessons`, `tasks` и поле `updatedAt`.

## 7. Проверьте облачную синхронизацию

1. На компьютере войдите через Google.
2. Создайте тестовый урок.
3. Обновите страницу — урок должен остаться.
4. Откройте сайт в другом браузере или на телефоне.
5. Войдите через тот же Google-аккаунт.
6. Урок должен появиться автоматически.
7. Отметьте его оплаченным на втором устройстве.
8. Проверьте, что состояние изменилось на первом устройстве.

Если пользователь не вошёл, сайт работает в демонстрационном режиме и сохраняет данные только в этом браузере. Локальные демо-данные не переносятся автоматически в облако после входа.

## 8. Включите Firebase Storage

Storage понадобится, когда к домашним заданиям будет добавлена загрузка PDF, DOCX или изображений. Текущая версия уже инициализирует Storage, но UI загрузки файлов является следующим этапом разработки.

1. Откройте **Build → Storage** или **Databases & Storage → Storage**.
2. Нажмите **Get started / Начать**.
3. Выберите регион. По возможности используйте регион, совместимый с выбранным регионом Firestore.
4. Завершите создание bucket.
5. Откройте вкладку **Rules / Правила**.
6. Скопируйте содержимое файла `storage.rules` из архива.
7. Вставьте его вместо текущих правил.
8. Нажмите **Publish / Опубликовать**.

Файлы должны сохраняться только по пути `users/{uid}/...`. Правила запрещают одному пользователю читать папку другого.

Важно: для новых Cloud Storage buckets могут действовать требования биллинга Google Cloud. Firebase Console покажет актуальные условия до создания bucket.

## 9. Нужно ли включать Analytics

Нет, для работы календаря Analytics не требуется. В конфигурации есть `measurementId`, но сайт не вызывает `getAnalytics`, поэтому:

- календарь работает без Analytics;
- вход и Firestore от Analytics не зависят;
- можно включить Analytics позже, если понадобится статистика посещений.

## 10. Локальный запуск сайта

1. Распакуйте `Teacher_Calendar_Website.zip`.
2. Откройте распакованную папку в Visual Studio Code.
3. Откройте **Terminal → New Terminal**.
4. Выполните:

```powershell
npm install
npm run dev
```

5. Откройте адрес, показанный в терминале, обычно `http://localhost:3000` или другой свободный локальный порт.
6. Нажмите `Войти` и проверьте Google-вход.

Если команда `npm` не найдена, установите актуальную LTS-версию Node.js и перезапустите Visual Studio Code.

## 11. Production-сборка

Перед загрузкой проверьте проект:

```powershell
npm run lint
npm run build
```

Обе команды должны завершиться без ошибок.

## 12. Публикация через Firebase Hosting

Этот проект использует современную серверную сборку, поэтому для простейшего размещения можно выбрать поддерживающий её хостинг. Если вы хотите именно Firebase Hosting, используйте Firebase CLI и настройте Hosting согласно выбранному способу рендеринга.

Базовые команды:

```powershell
npm install -g firebase-tools
firebase login
firebase init hosting
firebase deploy
```

Во время `firebase init hosting`:

1. выберите **Use an existing project**;
2. выберите `calendar-65f48`;
3. не соглашайтесь перезаписывать исходные файлы сайта;
4. внимательно выберите интеграцию, поддерживающую ваш фреймворк, а не настройку обычного статического `index.html`.

После публикации скопируйте выданный домен и добавьте его в **Authentication → Settings → Authorized domains**.

## 13. Частые ошибки

### `auth/operation-not-allowed`

Google provider не включён. Повторите раздел 2.

### `auth/unauthorized-domain`

Домен сайта не добавлен в Authorized domains. Повторите раздел 3.

### `Missing or insufficient permissions`

Проверьте:

- пользователь действительно вошёл;
- Firestore создан;
- правила из `firestore.rules` опубликованы;
- код работает с проектом `calendar-65f48`;
- данные записываются по пути `users/{uid}/...`.

### После входа исчезли демо-уроки

Это ожидаемо: демо-режим и облачный аккаунт используют разные хранилища. Создайте урок уже после входа.

### После обновления урок вернулся в старое состояние

Проверьте консоль браузера и Firestore Rules. Также убедитесь, что сайт открыт только в актуальной версии и не работает со старым кэшем.

### Время отличается на час

Проверьте выбранный UTC-offset на сайте. Для полноценной production-версии повторяющиеся серии должны хранить IANA time zone, например `Europe/Warsaw`, чтобы учитывать переходы на летнее время. Эта архитектура подробно описана в `Teacher_Calendar_AI_Specification.md`.

## 14. Безопасность

- Firebase Web API key не является административным паролем.
- Никогда не добавляйте в frontend Firebase Admin SDK private key или JSON service account.
- Не публикуйте правила `allow read, write: if true`.
- Проверяйте вкладку **Authentication → Users** и удаляйте неизвестные тестовые аккаунты.
- Перед реальным использованием проверьте правила через Firebase Rules Playground или Emulator Suite.
- Для единоличного календаря можно дополнительно ограничить доступ конкретным email, но UID-проверка уже изолирует данные каждого аккаунта.
